Bloque 0

Introduccion a JavaScript

JavaScript da comportamiento a la pagina: responde a eventos, calcula, valida, crea contenido y modifica el DOM que el usuario ve en pantalla.

Que hace JS en una web

  • Escucha acciones del usuario: clic, teclado, scroll, envio de formularios.
  • Lee datos de inputs, botones, textos e imagenes.
  • Cambia el HTML y el CSS sin recargar la pagina.
  • Puede guardar informacion en el navegador.

Flujo mental rapido

  • 1. El navegador construye el DOM a partir del HTML.
  • 2. JavaScript se ejecuta y selecciona elementos.
  • 3. Una accion dispara una funcion.
  • 4. El usuario ve el cambio en la interfaz.

Regla util: si el alumno no ve el resultado, suele costarle mas entender la teoria. Por eso cada bloque de esta clase intenta mostrar la salida dentro de la propia pagina.

Pulsa el boton para ver una accion sencilla hecha con JavaScript.

Esta demo no hace nada complejo: solo muestra el patron basico evento -> funcion -> cambio visible. 

// Patron minimo de interaccion
boton.addEventListener("click", function () {
  caja.textContent = "JavaScript acaba de reaccionar al clic";
});
Bloque 0.1

Donde situar la etiqueta <script>

El sitio donde cargas JavaScript importa porque determina si el DOM ya existe, si la pagina se bloquea y cuando empieza a ejecutarse el codigo.

La recomendacion general

  • Usar un archivo externo y cargarlo en el <head> con defer.
  • Asi el navegador sigue leyendo HTML y ejecuta el script cuando el DOM ya esta construido.
  • Tambien es valido poner el script al final del <body>.

Error tipico

Si intentas seleccionar un elemento antes de que exista en el DOM, normalmente obtendras null y despues fallara cualquier acceso como element.textContent. 

<!-- Opcion recomendada -->
<head>
  <script src="app.js" defer></script>
</head>

<!-- Opcion clasica -->
<body>
  ...
  <script src="app.js"></script>
</body>
Objetivo: ver por que importa el momento de carga
Este bloque se puede seleccionar porque el script principal esta colocado al final del body.
Bloque 1

Diferencias entre var y let

Las dos crean variables, pero no se comportan igual. El punto mas importante para iniciar suele ser el alcance o scope.

Con var

  • Tiene alcance de funcion, no de bloque.
  • Se puede redeclarar en el mismo ambito.
  • Su comportamiento historico provoca mas errores en codigo moderno.

Con let

  • Tiene alcance de bloque: if, for, while, etc.
  • No permite redeclarar en el mismo ambito.
  • Suele ser la mejor opcion para valores que cambian.
Aqui se mostrara la diferencia de alcance entre var y let. 
if (true) {
  var curso = "JavaScript";
}
console.log(curso); // existe

if (true) {
  let modulo = "DOM";
}
console.log(modulo); // error: modulo no existe fuera del bloque
Bloque 1.1

Hoisting en JavaScript

Hoisting no significa que el codigo "suba" visualmente, sino que durante la fase de preparacion el motor registra ciertas declaraciones antes de ejecutar linea a linea.

Resumen practico

  • Las function declarations se pueden usar antes de escribirlas.
  • var existe antes, pero con valor undefined.
  • let y const entran en zona muerta temporal hasta su declaracion.

Peligro habitual

Leer una variable declarada con let antes de su linea no devuelve undefined, sino un error. Eso ayuda a detectar fallos antes.

Pulsa un boton para ver como cambia la salida segun el tipo de declaracion. 
console.log(datoVar); // undefined
var datoVar = "listo";

console.log(datoLet); // ReferenceError
let datoLet = "listo";

saludar(); // funciona
function saludar() {
  console.log("hola");
}
Bloque 2

Formas de escribir desde JavaScript en un documento HTML

No todo "mostrar informacion" significa lo mismo. A veces quieres un aviso, otras una traza de consola, otras insertar contenido en la pagina.

Opciones frecuentes

  • alert(): mensaje emergente.
  • console.log(): depuracion para desarrollador.
  • textContent o innerHTML: escribir en el DOM.
  • document.write(): historico, hoy casi nunca recomendado.

Buena practica

Para explicar en clase es muy util combinar consola y resultado visual, porque asi el alumno ve tanto la depuracion como el efecto final.

Escribe algo en el input y prueba cada forma de mostrarlo.

La zona inferior usa un iframe vacio para demostrar document.write() sin destruir toda esta pagina. 

alert("Hola");
console.log("Hola");
document.getElementById("salida").textContent = "Hola";

// Mejor evitar esto despues de que la pagina ya este cargada:
document.write("Hola");
Bloque 3

Carga de scripts: normal, defer, async, DOMContentLoaded y load

Este es uno de los bloques mas utiles para entender por que un archivo JS funciona o falla segun cuando se ejecuta.

Lectura rapida de cada modo

  • Normal: descarga y ejecuta, bloqueando el parseo del HTML.
  • defer: descarga en paralelo y ejecuta al final, respetando el orden.
  • async: descarga en paralelo y ejecuta en cuanto llega, sin garantizar orden.

Eventos utiles

  • DOMContentLoaded: el DOM ya esta construido.
  • window.load: DOM y recursos externos ya han terminado.
  • Para manipular el DOM, normalmente con defer o DOMContentLoaded basta.

Bloque 4

Diferencia entre innerHTML, innerText y textContent

Parecen parecidos, pero no hacen lo mismo. Esta comparacion es clave cuando empiezas a modificar contenido desde JavaScript.

Al escribir

  • innerHTML interpreta etiquetas HTML.
  • innerText escribe texto visible, sin interpretar etiquetas.
  • textContent escribe texto plano de forma directa.

Al leer

  • innerHTML devuelve el HTML interno.
  • innerText devuelve el texto visible renderizado.
  • textContent devuelve todo el texto, incluso si hay nodos ocultos.
Texto visible Texto oculto dentro de span
Aqui veras el valor devuelto al leer cada propiedad. 
destino.innerHTML = "<strong>Hola</strong>";
destino.innerText = "<strong>Hola</strong>";
destino.textContent = "<strong>Hola</strong>";

console.log(origen.innerHTML);
console.log(origen.innerText);
console.log(origen.textContent);

Consejo de seguridad: si el contenido viene de un usuario, evita innerHTML salvo que limpies antes la entrada. Para texto normal, textContent suele ser la opcion mas segura.
